## 用户操作

保持 Script 为 Enable，确保相机本轮三分钟内保持开启；若平时的自动关机设置会更早关闭机身，先临时延长或关闭，实验后恢复原设置。关机时插卡并装好 GF-2。用手机等计时，普通开机后：

| 开机后大约时间 | 操作 |
| --- | --- |
| 立即 | 手动打开 GF-2，确认正常开启 |
| 30 秒 | 手动关闭 GF-2；相机保持开启 |
| 75 秒 | 确保 GF-2 已开启；若它此前已自行恢复，保持开启，不再按电源键 |
| 180 秒后 | 等卡读写结束，正常关机，取卡接电脑 |

期间保持相机空闲，不半按或拍照，不按其他机身键。后半段灯可能自行关闭或恢复；观察并记录实际指示，不再手动操作灯。计时点是人为安排的窗口，脚本自身的传输耗时还会叠加，不能当作实际精确发送时刻。

## 脚本自动阶段

| 大约时间 | 脚本行为 | 区分的问题 |
| --- | --- | --- |
| 16 秒 | C0–C5 开启基线 | 编号、状态、原始能力范围、C5 |
| 45 秒 | 三次 C0，间隔约 1 秒；再读取快照 | 按键关闭后是否响应重复查询 |
| 48–53 秒 | A6 `01 02`；等待 5 秒；再读取快照 | 正常参数是否与恢复相关；后续 C0 也是可能的唤醒来源 |
| 90 秒 | 再读开启基线 | 验证手动恢复后通信可用 |
| 90–113 秒 | A6 `01 00`；等待 20 秒；三次 C0 和快照 | 原厂关机参数后的查询响应 |
| 113–138 秒 | 再发 A6 `01 00`；20 秒后发 `01 02`；再等待 5 秒后读取 | 正常参数先于查询的恢复试验 |
| 约 138 秒后 | 恢复正常检测，写入全部测量结果 | 本轮完成及恢复返回值 |

实际时间含函数耗时。正常附件检测在整轮期间暂停，降低普通识别、AE 输出对实验的干扰；暂停并非硬件互斥锁。查询之前等待 1 秒，且每个原厂传输都自行开启、关闭通信。实验期间未做 SD 文件操作，结果暂存在脚本变量中，尝试恢复检测后再写日志。异常中止可能留下仅有开头的日志，不代表完成。

两次开启基线都必须 C0=A5 且 C1 kind 为 17/18（十六进制 11/12），才会继续相应测试部分。未收到 A5 时不继续读 C1–C5。退出路径均尝试恢复检测；已进入 A6 关机参数试验却提前退出时，还会尝试重发正常 `01 02`。命令返回 0 仍只是机身本地流程走完，不是附件确认。

## 结果位置与解释

卡根目录 `HSB2.TXT`。已有该文件则本脚本直接退出，避免每次开机重复试验。电脑另保存第一轮 `HSC0.TXT` 和上一版启动脚本，卡上也保留第一轮日志。

- C0 为 165：通信应答 A5。201/C9 可能是超时占位，不视为成功。
- C1 两字节：kind/subkind。若实际使用 GF-2且收到 17，可为 GF-2 对应 0x11 提供实机证据。
- C2 两字节：原始状态/标志；还不能将每个 bit 解释为具体电源状态。
- C3/C4：附件原始回复，未经过机身 kind 0x11 的范围替换。
- C5：原始校正输入，物理单位未知。
- `not reached`、-999：阶段未执行；负的本地命令返回：调用失败。
- 恢复返回为 0：恢复命令的本地正常返回，不是物理读回证明。

必须结合灯的指示与恢复就绪情况判断。A6 `01 00` 对灯有无实际关闭作用需要观察确认；在没有实际关闭的情况下，随后收到 A5 不能证明叫醒了灯。`01 02` 后 5 秒才查询，若灯在这段间隔中已自行恢复，更支持 A6/通信开启边沿的作用；只在后续 C0 时恢复，则不能归因于 A6。

这轮不会自动拍照。确认脚本结束、恢复检测成功之后，可另行核对实际闪光能力。联动关机参数的模拟也不等同于真的切断相机电源，因为本轮机身和电气环境始终保持开启。
