# GR IV / GF-2 A6 电源参数实测 v4

2026-10-13。v4 已由用户在 GF-2 上完整执行。用户明确确认灯先自行关闭，之后没有自行打开。此前 v3 的 C0–C5 查询完整通过，GF-2 回复 C1 `11 00`，图标和关机联动恢复。

## 实测结果

`HSP4.TXT` 共 1,267 字节，SHA-256 `45865fb010cd0b5dce1fb5988a0448d62e01197c30d507940f384d8e64e22ad8`。11 个阶段均有 BEGIN/END，结尾为 `ALL STEPS COMPLETE; checking restored.`；启动及 step 1、6、10 的恢复检测命令均返回 0。对应启动脚本为 5,124 字节，SHA-256 `02bd820a1a7d2c165381a16c0acbfcab1b470493362ce8e89a576515f3a0e74a`。

| 阶段 | 原厂 RX 缓冲读数 / 观察 |
| --- | --- |
| 灯开启基线 | C0=`A5`；C1=`11 00` |
| A6 `01 00` 后等待 20 秒 | 用户确认灯自行关闭；后续三次 C0 均为 `00` |
| 再发 `01 00`，等待 20 秒，再发 `01 02`，等待 5 秒 | C0 仍为 `00`；用户确认没有自行开灯 |
| 条件 C2 | 两组均因未收到 A5 而跳过，日志值 -998 |
| 正常检测恢复 | 各处恢复命令返回 0；用户尚未检查手动开灯后的图标和关机联动 |

这是已完成的负面实测：**本次 A6 `01 00` 导致可见关闭；随后重复 C0 查询及正常 A6 `01 02` 参数都未恢复 A5 或自动开灯。** 与 v2 的不完整日志不同，本轮已记录每个阶段的执行结果。

它不能证明所有热靴唤醒都不可能，也不能把 RX=`00` 解释为灯主控彻底断电、某种睡眠状态或确定的超时。原厂传输函数的本地返回 0 不等于灯端 ACK；没有波形或灯内部取证，无法区分线路电平和实际发送的回包。A6 参数完整语义、实际关闭延时也未测定。

原始日志及卡上启动脚本已读回逐字节保存于 `devkit-output/gr4-hotshoe-a6-test-20261013-v4/actual-return/`，解析和用户观察在 `v4-result.json`。下一轮比较按键关闭状态，并加入手动重新开灯后的通信基线，见[v5 对照测试](2026-10-13-gr4-hotshoe-manual-power-v5.md)。

## 用户只需操作

关机时装好 GF-2、插卡，保持 Script 已启用。普通开机后立即打开 GF-2，随后保持机身开启 **120 秒**，等待卡读写结束。期间不手动开关灯、不半按或拍照；观察灯是否自动关闭、以及是否自行恢复。若机身自动关机设置不足两分钟，先临时延长或关闭。

正常关机后取卡接电脑，读取 `HSP4.TXT`。请同时记录：灯有没有实际熄灭/关闭，后来有没有自行恢复，还是始终保持开启。相机保持通电的参数模拟不等于真正关闭机身电源。

测试区间会短暂暂停普通检测，因而图标可能消失。基线、第一组、第二组结束时均尝试恢复检测，最后记录完成。已有 `HSP4.TXT` 时，下一次正常开机先恢复检测、再跳过试验，避免重复发送参数。若最终灯处于关闭状态，按正常顺序重新开机身、再手动开灯即可核对正常联动。

## 自动阶段

| Step | 操作 | 回答的问题 |
| --- | --- | --- |
| 0 / 1 | C0 / C1 开启基线，要求 A5 且 kind 为 0x11/0x12 | 当前附件通信是否正常 |
| 2 | A6 `01 00`，等待 20 秒 | 固件关机路径构造的参数是否实际使灯关闭 |
| 3 / 4 / 5 | 三次 C0，间隔约 1 秒 | 相同查询重复后是否恢复回应 |
| 6 | 若上一条 C0 为 A5，读取 C2；恢复检测 | 查询后状态，第一组正常恢复 |
| 7 | 再发 A6 `01 00`，等待 20 秒 | 准备再次比较；若灯此前仍关闭，参数是否接收未知 |
| 8 | A6 `01 02`，等待 5 秒 | 正常默认参数是否在后续查询之前使灯恢复 |
| 9 / 10 | C0，收到 A5 则读取 C2；恢复检测 | 正常参数后的回应及最终恢复 |

显式等待总计 67 秒，实际时间另含启动、原厂函数与 SD 操作，因此要求保持开机 120 秒。A6 命令的回包未作为 ACK 使用；其本地返回 0 只表示机身处理函数正常返回。

每条传输前后立即向卡写记录。为避免正常轮询在等待期间改变灯状态，电源测试区间保持检测暂停；记录文件操作也在该区间执行。文件打开失败和已检查的调用错误进入恢复路径；任意解释器异常/不返回仍无法依赖本轮清理，下一次启动的先恢复路径是独立的补救。

首次 A6 `01 00` 试验后如提前退出，会先尝试发送正常 `01 02`，再恢复检测。这个动作不是已证明的唤醒，也不保证附件收到。实验使用原厂已知字节，不发送主输出 A0 或未知命令。

## 日志解释

`BEGIN step` / `END step` 确定最后进入和完成的阶段。每阶段按 RX0、RX1、本地传输返回、该阶段恢复返回排列：

- -999：本项不用，或该阶段尚未执行恢复。只在 step 1、6、10 正常执行恢复，因此其他阶段恢复为 -999 是预期。
- -998：没有 A5，跳过 C2；不是机身函数返回值。
- C0 的 165=A5：通信应答，不单独证明充电或完整开机。
- C0 的 201=C9：可能是超时占位，也可能是真实字节，不能作为成功应答。
- 最后 `ALL STEPS COMPLETE; checking restored.`：全部阶段已记录；仍需结合实际灯状态判断。

如果 `01 00` 没有实际关闭灯，后续 A5 不能算唤醒成功。若 `01 02` 后等待的 5 秒内已经恢复，更支持该参数或通信开启边沿的作用；若直到后续 C0 才恢复，不能单独归因于 A6。若有回应却指示/充电未恢复，只能确认收发仍有能力。
